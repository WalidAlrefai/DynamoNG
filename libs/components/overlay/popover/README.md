# @dynamong/popover

A click-to-open panel anchored to a trigger element, for richer content than
a tooltip can hold (a form, a color swatch grid, a details card). Traps
focus while open and returns it to the trigger on close.

## Usage

```html
<dg-popover [(open)]="isOpen" position="bottom-start">
  <dg-button (click)="isOpen.set(true)">Open</dg-button>
  <dg-popover-content>
    <p>Popover body content, rendered through the CDK-portaled panel.</p>
  </dg-popover-content>
</dg-popover>
```

```ts
protected readonly isOpen = signal(false);
```

## Inputs

| Input                  | Type                    | Default          | Description                                                             |
| ---------------------- | ----------------------- | ---------------- | ----------------------------------------------------------------------- |
| `position`             | `DynamoPopoverPosition` | `'bottom-start'` | Preferred corner; the other three are tried as CDK collision fallbacks. |
| `ariaLabel`            | `string \| undefined`   | `undefined`      | Labels the panel.                                                       |
| `open`                 | `boolean` (model)       | `false`          | Two-way bindable panel open state.                                      |
| `closeOnBackdropClick` | `boolean`               | `true`           | Whether clicking outside the panel closes it.                           |

The projected `<dg-popover-content>` renders no DOM of its own — it only captures its content as a `TemplateRef` that the panel stamps out via `ngTemplateOutlet`, so the body can live in a CDK-portaled overlay rather than the trigger's fixed DOM position. Everything projected into `<dg-popover>` that is _not_ a `<dg-popover-content>` becomes the trigger.

## Outputs

| Output       | Payload   | Fires when                                    |
| ------------ | --------- | --------------------------------------------- |
| `openChange` | `boolean` | `open` changes (auto-generated by `model()`). |

## Accessibility

- The panel is focus-trapped (`ConfigurableFocusTrap`) while open, receives initial focus, and returns focus to whatever was previously focused on close.
- `Escape` closes the panel and refocuses the trigger; when `closeOnBackdropClick` is `true`, clicking outside does the same without refocusing.
- The trigger wrapper responds to `Enter`/`Space` when it itself is the focused/clicked target — keyboard operability is otherwise expected to come from the projected trigger content (e.g. a `<dg-button>`).
