# @dynamong/date-range-picker

A two-date range picker built on the same month-grid calendar as
`@dynamong/date-picker` — click a start date, then an end date, with a
live hover/keyboard preview of the in-progress range. Implements
`ControlValueAccessor`, so it also works with `formControl`/`ngModel`.

## Usage

```html
<dg-date-range-picker
  [(value)]="selectedRange"
  [min]="minDate"
  [max]="maxDate"
  ariaLabel="Booking dates"
/>
```

```ts
protected readonly selectedRange = signal<DynamoDateRange>({
  start: null,
  end: null,
});
```

## Selection behavior

- **First click** sets `start` (and clears `end`); the panel stays open.
- **Second click** sets `end` and commits, closing the panel. Clicking a
  date _before_ the current `start` redefines the range — the click
  becomes the new, earlier boundary — rather than resetting the selection.
  A same-day second click yields a valid 1-day range (`start === end`).
- While picking the end date, hovering (mouse) or moving focus (keyboard)
  over a day previews the tentative range — the preview never mutates
  `value()` until a day is actually committed.
- `onChangeFn`/`valueChange` fire on **both** steps — a partial
  `{ start, end: null }` is a legitimate transient value for a bound
  `FormControl`, not suppressed until the range is complete.

## Month/year quick-jump

Identical to `@dynamong/date-picker`'s: clicking the month/year header
label swaps the day grid for a month-button grid with a year stepper.
`Escape` closes the quick-jump grid first, then the panel on a second
press.

## Accessibility

- Trigger is a native `<button>` with `aria-haspopup="dialog"`, `aria-expanded`, `aria-controls`, `aria-invalid`, `aria-readonly`.
- Panel is `role="dialog"` (`aria-modal="false"`) containing a `role="grid"` calendar, with each range endpoint cell marked `aria-selected`.
- Each day button carries a full formatted-date `aria-label`, with a
  "start of range"/"end of range" suffix on the two endpoint days (e.g.
  "August 19, 2026, start of range").
- A visually-hidden `aria-live="polite"` region announces the visible
  month whenever it changes.
- Keyboard: identical to `@dynamong/date-picker` (roving focus, `Home`/`End`,
  `PageUp`/`PageDown`, `Shift+PageUp`/`Shift+PageDown`, `Escape`) — selecting
  a day is native `<button>` Enter/Space behavior, so both range endpoints
  can be set entirely from the keyboard.

## Design notes

**Single calendar grid, not a dual-month view.** This v1 deliberately
reuses `@dynamong/date-picker`'s single 42-cell month grid rather than a
side-by-side two-month layout — the month/year quick-jump makes crossing
months fast enough to compensate. A dual-pane view is a natural next step
once this grid code has settled, not a gap in this pass.

**Shares `@dynamong/date-picker`'s pure helpers.** `buildCalendarGrid`,
`clampToRange`, `isDateDisabled`, and `getCachedDateTimeFormat` are
imported from `@dynamong/date-picker` rather than duplicated, mirroring
the precedent `@dynamong/multi-select` already sets for depending on a
sibling's shared internals (`DynamoListboxBase`, from `@dynamong/select`).

## Tier / dependencies

- `tier:3`. Peer dependencies: `@dynamong/select` (CDK Overlay lifecycle via `DynamoListboxBase`), `@dynamong/date-picker` (shared calendar/formatting helpers).
